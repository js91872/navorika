3. NATIVE OCCT CONVERTER ENGINE (step-to-obj) SPECIFICATION & PERFORMANCE
================================================================================
The native converter step-to-obj is written in modern C++17 utilizing Open CASCADE
Technology 7.6.

Engine Features:
- Direct STEP read via STEPControl_Reader with IFSelect_RetDone status verification.
- Model analysis counting TopAbs_SOLID, TopAbs_FACE, TopAbs_EDGE, TopAbs_VERTEX.
- Standard deflection-based incremental meshing via BRepMesh_IncrementalMesh.
- Linear deflection parameter: 0.1mm (configurable via CLI).
- Angular deflection parameter: 0.5 rad (~28.6 degrees).
- Bounding box computation via BRepBndLib::Add.
- Clean Wavefront OBJ emission with explicit normals (vn) and facet definitions (f).
- Structured JSON metadata output emitted to stdout for Node.js ingestion.
- Diagnostic logs and OCCT warnings isolated to stderr.

Binary Characteristics:
- Location: bin/step-to-obj
- File Size: ~46 KB (dynamically linked against libTKSTEP, libTKMesh, libTKBRep, etc.)
- Startup & execution time: ~0.4 seconds for an 888 KB STEP model with 118 faces.

10. HEADLESS RENDERING & PIPELINE ARCHITECTURE (settings.render=0)
================================================================================
Server Environments & Offscreen Rendering:
- Production hosts and developer containers are typically headless (no X11 / Wayland).
- By default, Asymptote attempts to invoke OpenGL/freeglut to render a 2D raster
  poster snapshot (render=2), which fails in headless Linux without an active DISPLAY.
- Architecture Solution: We explicitly enforce `settings.render = 0;` inside the
  generated Asymptote script.
- Result: Asymptote compiles PRC streams purely via vector Math/LaTeX without requiring
  X11, GPU drivers, or an Xvfb virtual framebuffer display wrapper.
- Resulting PDF contains native vector graphics and PRC streams.

11. SECURITY, ISOLATION & RESOURCE CONTROLS
================================================================================
1. Input Sanitization & Magic Header Verification:
   - Upload file size capped at 25 MB.
   - Header inspection: Verifies ASCII/UTF-8 buffer begins with "ISO-10303-21;"
     and contains "HEADER;" section to prevent arbitrary file execution.

2. Sandboxed File Execution:
   - Each conversion creates an isolated ephemeral directory:
     /tmp/navorika-cad-XXXXXX/
   - Files are written with restricted permissions.
   - Guaranteed cleanup in try/finally blocks via rm(dir, { recursive: true, force: true }).

3. Subprocess Safety:
   - Child processes are spawned directly with { shell: false }.
   - Arguments are passed as arrays; no shell string interpolation exists.
   - Execution timeout enforced at 60,000 ms with SIGKILL termination.
   - Internal filesystem paths and system errors are stripped from user HTTP responses.

4. Server Concurrency & DOS Protection:
   - Maximum concurrent CAD conversions gated by AsyncSemaphore (MAX_CONCURRENT_CAD_JOBS = 2).
   - Rate limiting headers enabled on upload endpoints.

14. KNOWN LIMITATIONS & VIEWER COMPATIBILITY GUIDELINES
================================================================================
CRITICAL PDF VIEWER REQUIREMENTS:
- Standard browser PDF viewers (Google Chrome, Mozilla Firefox, Microsoft Edge, Safari)
  do NOT support interactive 3D PRC / U3D engines. They render either the 2D vector
  placeholder sheet or display a blank page.
- Linux open-source viewers (Evince, Okular) have limited or no PRC support.
- Intended & Supported Viewer: Adobe Acrobat Reader (Desktop - Windows / macOS).
- User Notice: The conversion page and download card feature clear callouts advising
  users to open the generated PDF in desktop Adobe Acrobat Reader.

Geometry & File Size Limits:
- Upload size limit: 25 MB.
- Assemblies with over 500,000 triangles may experience prolonged conversion times
  (>30s) or viewer sluggishness on low-spec client machines.
